# L1 Cache (黑板系統 / Blackboard)

L1 是系統的當前工作空間，扮演著「中央數據交換站」與「認知投影台」的角色。

## 1. 實體存儲定義 (Physical Storage)
- **本體**: **字串鍵值對存儲系統 (String-based Key-Value Storage)**。
- **存儲路徑**: `workspace/sessions/<sessionId>/blackboard.json`。
- **隔離級別**: **Session 專屬 (Session-Scoped)**。
- **數據結構**: 
    - 以單一 JSON 文件存儲，支援 O(1) 的快速全量加載。
    - 每個條目包含：
        - **Key (鍵名)**: 唯一識別標識（如 `db_connection_string`）。
        - **Value (值)**: **純字串內容**。複雜結構應序列化後存儲。
        - **Description (描述)**: 數據含義的自然語言說明，用於語義對齊。

## 2. 投影與掛接機制 (Projection & Shadowing)
- **投影容器**: L1 是所有長期記憶 (L2/L3) 在當前任務中的「投影門戶」。
- **自動預載入 (Pre-loading)**: 當任務啟動時，系統會從 L2 與 L3 提取相關索引，並在 L1 中建立「影子鍵 (Shadow Keys)」。
- **命名空間前綴**: 投影後的 Key 會標註來源以區分作用域：
    - `global:fact_name`: 來自全域 L2 的事實。
    - `session:fact_name`: 來自當前會話 L2 的事實。
    - `sop:sop_name`: 指向 L3 SOP 的索引。

## 3. 認知投影策略 (Cognitive Projection)
- **Key-Only 投影**: 為了節省 Token，注入 Agent Prompt 的內容僅包含 **Key** 與 **Description**。
- **按需加載 (On-demand Fetching)**: Agent 在 Prompt 中看到 Key 後，若需要其具體的 **Value**（不論是實體數據還是 SOP 全文），必須主動呼叫 `read_blackboard(key)` 或 `fetch_sop(key)` 工具。

## 4. 語義對齊 (Semantic Alignment)
- **描述驅動**: Agent 透過比對步驟描述與黑板中各 Key 的 **Description**，利用 LLM 的推理能力實現動態數據掛接。

## 5. 工具鏈支援
- `write_blackboard(key, value, description)`: 寫入或更新數據與其含義。
- `read_blackboard(key)`: 讀取實體 Value。
- `list_keys()`: 獲取當前黑板的索引清單（含描述與命名空間）。
