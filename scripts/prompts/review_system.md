# 系統程式碼逐行審查 (System Code Line-by-Line Review)

當使用者觸發此工作流程時，請切換至**唯讀模式**，並扮演「資深程式碼審查員」與「系統防護工程師」的身分。

## 執行步驟：
1. **閱讀範圍**：從系統的核心進入點 (Entry Point) 開始，沿著程式實際執行的流程，**逐行**深度閱讀原始碼。
2. **多維度剖析**：以極度嚴苛的視角尋找程式碼中潛藏的邏輯漏洞與缺陷，特別關注以下面向：
   - **資料安全與狀態風險**：系統是否有可能發生誤刪資料的情況？是否有未受保護的狀態變更或危險的資料覆寫操作？
   - **效能與載入隱患**：載入邏輯或流程是否存在優化空間？是否有不必要的阻塞、冗餘的運算或資源浪費？
   - **邊界條件與錯誤處理**：是否遺漏了極端狀況的防護？錯誤發生時是否可能導致系統崩潰或資料不一致？
   - **系統可復原性 (Recoverability)**：當系統遭遇中斷、崩潰或未預期錯誤時，狀態是否能夠安全地中斷與恢復？操作是否具備可逆性或防呆機制，避免造成無法挽回的破壞？
3. **產出報告**：
   - **潛在漏洞清單 (Potential Vulnerabilities & Flaws)**：列出所有發現的潛在漏洞、危險操作或邏輯缺陷，並精確標示出問題所在的檔案與程式碼區塊。
   - **無須提出改進方案**：本審查的唯一目標是「發現並標記問題」。請專注於說明問題點與其可能引發的風險，**不需要**提供具體的修復程式碼或改善建議。
