# 需求對齊與構想探討流程 (Ideation Workflow)

在進行任何具體代碼實作前，請嚴格遵守 `GEMINI.md` 的開發迭代流程，啟動此「認知先行」工作流。

## 執行步驟：
1. **需求理解與澄清**：
   - 總結使用者提出的功能需求。
   - 主動詢問模糊地帶或潛在的邊界條件 (Edge Cases)。
2. **架構設計探討**：
   - 評估新功能應歸屬於哪個核心模組 (`core` 或 `package`)。
   - 思考如何透過 `EventBus`、`DataBlock` 或 `BaseAgent` 等既有基礎設施來達成，避免破壞系統現有的解耦設計與生命週期。
3. **實作路徑規劃**：
   - 提出 1~2 種高階技術方案，分析優缺點。
   - 討論 LLM API 的呼叫時機，確保符合授權規範。
   - 與使用者確認並達成共識。
4. **禁止寫扣**：在此階段**嚴禁**產出任何具體專案程式碼。
5. **下一步提示**：達成共識後，主動提示使用者進入「文件落實與架構同步 (`workflow_docs_sync.md`)」流程。
