### Step 1: 採用多來源交叉比對，處理 API 回傳看似成功但數值不合理的情況

**Plan Draft**: 
Objective: 開發一個本地執行的加密貨幣追蹤工具，從外部 API 取得 BTC 與 ETH 價格、計算價差並輸出 HTML 報告，且在 API 斷線或資料異常時提供可靠結果。

Plan:
1. 選擇主要與備援資料來源
   - 設定主要 API 及至少一個備援 API，統一資產符號、幣別與價格欄位格式。

2. 取得並標準化資料
   - 依序呼叫主要來源；遇到連線錯誤、逾時、非成功 HTTP 狀態或無效 JSON 時執行重試。
   - 重試失敗後切換備援來源，而不是把錯誤回應當作價格。
   - 將各來源資料轉成統一的數值、時間戳與來源結構。

3. 執行多層合理性檢查
   - 檢查價格為有限正數、幣別正確、時間戳不過舊。
   - 比較不同來源的價格；若相對差異超過門檻，標記為來源不一致並拒絕自動選擇，或依預先定義的可信度規則選用並在報告警告。
   - 與最近一次有效結果比較，偵測不合理的瞬間暴漲或暴跌。
   - 未通過檢查的資料不得用於計算或覆寫快取。

4. 定義故障決策
   - 主要來源失敗、備援成功且驗證通過時，使用備援並標示來源切換。
   - 所有來源失敗時，若有仍在有效期限內的快取則降級使用；否則產生無法計算的錯誤報告。
   - 若 BTC 與 ETH 使用的來源或資料時間差過大，顯示資料不可直接比較，避免輸出誤導性價差。

5. 計算與產生 HTML
   - 僅對通過驗證且時間條件一致的兩筆價格計算絕對價差及百分比差異。
   - 顯示價格、價差、來源、取得時間、備援切換、資料一致性檢查與所有警告。
   - 無法計算時仍輸出狀態清楚的 HTML，避免使用空值或零值冒充結果。
   - 以安全 escaping 處理文字，並用暫存檔及原子替換保護報告檔案。

6. 可觀測性與測試
   - 記錄每個來源的請求、重試、切換、數值檢查與最終決策。

### Step 2: 建立明確的 API 容錯與重試狀態機，具體化斷線、HTTP 錯誤、速率限制與 circuit breaker 行為

**Plan Draft**: 
Objective: 開發一個本地執行的加密貨幣追蹤工具，從外部 API 取得 BTC 與 ETH 價格、計算價差並輸出 HTML 報告；當 API 斷線、逾時、回傳錯誤格式或不合理數值時，工具不得產生誤導性結果，且必須提供可追蹤的降級狀態。

Plan:
1. 定義資料來源與統一資料模型
   - 設定主要 API 與至少一個備援 API，明確記錄 endpoint、交易對格式、報價幣別、回應欄位與時間戳欄位。
   - 所有來源統一轉換為：asset、price、quote_currency、source、fetched_at、provider_timestamp、request_id、validation_status。
   - 價格必須使用同一報價幣別；若來源幣別不同，先依明確且可驗證的匯率規則換算，否則標記為不可比較。
   - 使用 UTC 時間戳與固定精度，拒絕無法解析、未來時間或過度陳舊的資料。

2. 設計單一 API 請求的重試流程
   - 每次請求設定連線逾時、讀取逾時、總請求期限與最大重試次數，例如總期限不得超過本次執行的全域 deadline。
   - 對網路斷線、DNS 失敗、連線逾時、HTTP 408、425、429、500、502、503、504 執行有限次數重試；對 400、401、403、404、格式錯誤及明確業務錯誤不重試，直接切換來源或失敗。
   - 使用指數退避加隨機抖動；HTTP 429 若提供 Retry-After，優先遵循但不得超過全域 deadline。
   - 每次重試記錄來源、錯誤類型、等待時間與剩餘期限，但不得記錄 API key。
   - 當請求成功回應但 JSON 不完整、欄位缺失、數值為 NaN/Infinity、非有限正數、幣別不符或時間戳不合理時，視為資料驗證失敗，不得把該回應當成有效價格。

3. 實作來源健康狀態與切換
   - 為每個來源維護 CLOSED、OPEN、HALF_OPEN 三種 circuit breaker 狀態。
   - 連續發生連線失敗、超時、服務端錯誤或資料驗證失敗時累計失敗次數；超過門檻後暫停呼叫該來源一段冷卻時間。
   - 冷卻時間後只允許有限的探測請求；驗證通過才恢復主要來源，否則延長冷卻時間。
   - 每次執行優先使用健康的主要來源，失敗後依序使用備援來源；來源切換必須顯示在結果與日誌中。
   - 不因單次短暫失敗永久停用來源，也不在同一執行中無限制重試。

4. 並行取得 BTC 與 ETH 並處理部分失敗
   - 在全域 deadline 內並行取得 BTC 與 ETH，以縮短兩筆資料的時間差；每個資產各自執行主要來源、重試與備援切換流程。
   - 分別記錄每個資產的來源、取得時間與驗證結果。
   - 若一個資產成功、另一個資產失敗，不得以零值或空值計算價差；依快取政策判斷是否可使用該資產的有效快取。
   - 若兩筆資料時間差超過設定門檻，即使數值有效，也標記為不可直接比較，除非明確啟用並顯示降級比較模式。

5. 執行數值合理性檢查
   - 檢查價格是否為有限正數、幣別與交易對正確、時間戳不過舊且不在未來。
   - 比較同一資產的多來源價格；相對差異超過設定門檻時標記來源矛盾，不自動選用未經規則確認的數值。
   - 與最近一次有效結果比較，偵測不合理瞬間變化；首次執行沒有歷史資料時，只執行格式、範圍與跨來源檢查，不因缺少歷史而判定失敗。
   - 所有門檻、TTL、價格跳變比例與百分比差異分母均放入版本化設定檔，不硬編碼在流程中。

6. 定義故障決策矩陣
   - 主要來源成功且驗證通過：使用主要來源，狀態為 SUCCESS。
   - 主要來源失敗、備援成功且驗證通過：使用備援，狀態為 DEGRADED，報告顯示切換原因。
   - API 回傳成功但資料不合理：視同來源失敗，禁止計算，並列出驗證錯誤。
   - 一個資產成功、另一個資產失敗：只有在失敗資產的快取仍未過期且驗證通過時才允許降級計算，否則狀態為 PARTIAL_FAILURE。
   - 所有來源失敗且沒有有效快取：輸出不可計算的 ERROR 報告，不使用零值、舊值冒充即時值。

7. 快取與輸出
   - 將每個資產的最後有效資料及驗證資訊寫入版本化快取；使用暫存檔、fsync（可行時）與原子替換，處理損毀、權限不足、磁碟滿與時鐘倒退。
   - 快取有明確 TTL；過期快取不得參與計算，只能作為診斷資訊。
   - 僅使用兩筆均通過驗證且時間條件一致的資料計算絕對價差與百分比價差，明確定義百分比分母。
   - 以暫存 HTML 加原子替換產生報告；對所有外部資料進行 HTML 文字與屬性 escaping。
   - 報告列出價格、來源、取得時間、重試、切換、circuit breaker 狀態、驗證錯誤、快取使用與最終決策。

8. 可觀測性、介面與測試
   - 提供 CLI、設定檔與輸出路徑選項；定義 SUCCESS、DEGRADED、PARTIAL_FAILURE、ERROR 的退出碼。
   - 使用可注入的 clock、network client 與 fixture 測試：斷線、DNS 失敗、逾時、429、5xx、malformed JSON、缺欄位、NaN/Infinity、負數、零、錯誤幣別、未來時間戳、來源矛盾與異常尖峰。
   - 測試重試上限、退避、deadline、circuit breaker 恢復、部分成功、快取損毀與 HTML 內容，並驗證任何不合理數值都不會進入計算。
